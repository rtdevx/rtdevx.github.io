The first and the most fundamental thing for the Lambda function to run is: the code.

Function name #

  • Required Argument
  • Must be unique inside of the region and the AWS Account

Because Lambda Function Name must be regionally unique, therefore using fixed Lambda Function name within a Terraform module will not work.

‼️For Terraform modules, use random_id resource (see below).

resource "random_id" "id" {
  byte_length = 8
}

resource "aws_lambda_function" "lambda" {
  function_name = "friendly_name-${random_id.id.hex}"
}

More: Terraform Registry: random_id

Handler #

(Optional) Function entry point in your code. Required if package_type is Zip.

This is where Lambda Function finds it’s entry point in the zip file.

Runtime #

(Optional) Identifier of the function’s runtime. Required if package_type is Zip.

The runtime is the software environment in which the function runs.

runtime = "nodejs12.x"

Lambda Runtime Support Policy #

AWS Lambda runtimes are managed through a lifecycle that includes introduction, support, and eventual deprecation. This policy ensures that users have access to secure and updated runtimes for their serverless applications.

Important Considerations

  • End-of-Life (EOL): Once a runtime reaches EOL, it will not receive any further security updates or technical support. Users are encouraged to migrate to supported runtimes to avoid vulnerabilities.
  • Upgrade Recommendations: It is advisable to upgrade to the latest Long Term Support (LTS) version of a runtime to ensure continued support and security.
  • Monitoring: Users should regularly check AWS notifications and Trusted Advisor for updates on deprecated runtimes and plan migrations accordingly.

‼️ More: AWS Lambda Function Runtimes

✨Execution role #

role (Required) ARN of the function’s execution role. The role provides the function’s identity and access to AWS services and resources.

role          = aws_iam_role.example.arn
The Execution Role defines which AWS resources the Lambda function can access.

Lambda Code Sources #

AWS Lambda supports three code sources when managed through Terraform:

  • Local ZIP file (filename)
  • ZIP stored in S3 (s3_bucket + s3_key)
  • Container image stored in ECR (image_uri)

Basic Function with Node.js #

# Package the Lambda function code
data "archive_file" "example" {
  type        = "zip"
  source_file = "${path.module}/lambda/index.js"
  output_path = "${path.module}/lambda/function.zip"
}

# Lambda function
resource "aws_lambda_function" "example" {
  filename      = data.archive_file.example.output_path
  function_name = "example_lambda_function"
  role          = aws_iam_role.example.arn
  handler       = "index.handler"
  code_sha256   = data.archive_file.example.output_base64sha256

  runtime = "nodejs24.x"
}

When using ECR, the Lambda runtime and handler are defined inside the container image, not in Terraform. Terraform only needs:

  • function_name
  • role
  • package_type = "Image"
  • image_uri

So the “runtime” and “handler” requirement applies only to ZIP‑based Lambdas.

Container Image Function #

resource "aws_lambda_function" "example" {
  function_name = "example_container_function"
  role          = aws_iam_role.example.arn
  package_type  = "Image"
  image_uri     = "${aws_ecr_repository.example.repository_url}:latest"

  image_config {
    entry_point = ["/lambda-entrypoint.sh"]
    command     = ["app.handler"]
  }

  memory_size = 512
  timeout     = 30

  architectures = ["arm64"] # Graviton support for better price/performance
}

More: Terraform Registry: aws_lambda_function

Optional Settings #

Log group #

Lambda uses CloudWatch Logs to store its logs. This is set up automatically and doesn’t need to be configured except of permissions.

Lambda Function requires IAM permissions to create a Log Group. Log group name is fixed and can’t be changed: /aws/lambda/{function-name}.

Under a Log Group, there are a multiple Log Streams. Log Streams contain Log Entries.

#

CloudWatch Lifecycle policies should be created when creating Lambda Functions otherwise logs never expire (default) and are not deleted automatically.

✨Terraform managed Log Group #

  1. Create a Log Group resource
resource "aws_cloudwatch_log_group" "loggroup" {
  name              = "${aws_lambda_function.lambda.function_name}"
  retention_in_days = 14

  tags = {
    Environment = "production"
    Application = "serviceA"
  }
}
  1. Remove the logs:CreateLogGroup

#

Remove logs:CreateLogGroup permission from the Lambda Function.

When both - Lambda and Terraform can create the LogGroup, it could create the race condition. By removing the permissions from the Lambda Function, you ensure Terraform will be the one that is managing the resource.
